## Specific findings

### F-1 — Sei row in chain-comparison table contradicts its own citation [MEDIUM]

**Files:**
- `content/posts/2026-04-23-p256-precompile-mainnet-live.mdx` (Hera "How We Win" table, Sei row)
- `app/hip/page.jsx` (HIP-001 ADOPTION list, Sei link)
- `hela-ai-contracts/docs/P256_PRECOMPILE_TECH_DOC.md` (Adoption section, Sei link)

**Claim:** Sei runs RIP-7212 at 3,450 gas (table row: `Sei | RIP-7212 | 3,450 | not checked | plain equality | Sei docs`).

**What the cited source actually says** (https://docs.sei.io/evm/precompiles/p256-precompile, fetched 2026-04-30):
- Address: `0x0000000000000000000000000000000000001011` — **NOT** the RIP-7212 standard `0x100`
- Gas: `GasCostPerByte = 300`, total `300 × 160 = 48,000 gas per verification` — **NOT** 3,450 fixed

Sei's docs do say "This is the implementation of RIP-7212" and use the same 160-byte input format, so calling it RIP-7212-flavoured is defensible. But the table column **"Gas: 3,450"** is wrong by ~14× for this specific row, and the Sei row is the only row in the table where the cited source directly contradicts the claim. This is exactly the kind of error the gate is supposed to catch.

**Recommended fix:** Either (a) change Sei row to `Gas: 48,000* (per-byte)` with a footnote explaining the divergence, or (b) drop Sei from the table entirely (same precedent as Celo) and keep only chains that actually run RIP-7212 at 3,450 fixed gas. Option (b) is cleaner and avoids the implication that Sei's spec is a drop-in equivalent for tooling purposes (it isn't — different address breaks `address(0x100).staticcall(...)` examples).

### F-2 — "ArbOS 30" should be "ArbOS 31 'Bianca'" [MEDIUM]

**Files:**
- `content/posts/2026-04-23-p256-precompile-mainnet-live.mdx` (table row + sources list)
- `app/hip/page.jsx` (ADOPTION list + SOURCES list — 2 occurrences)
- `hela-ai-contracts/docs/P256_PRECOMPILE_TECH_DOC.md` (Adoption section + Sources)

**Claim:** Arbitrum activated RIP-7212 in **ArbOS 30**.

**What the cited source actually says** (https://forum.arbitrum.foundation/t/aip-support-rip-7212-for-account-abstraction-wallets-arbos-30/23298, confirmed via WebFetch): the AIP carries an "ArbOS 30" slug because the original proposal was drafted for ArbOS 30, **but the proposal was superseded** and RIP-7212 was ultimately bundled into "ArbOS 31 'Bianca'" alongside Stylus and the Nova Fee Router. The forum thread itself references the ArbOS 31 supersedure repeatedly.

We're citing a forum thread whose URL slug doesn't match what shipped on mainnet. The cited link does resolve and does discuss RIP-7212 on Arbitrum, so the citation isn't broken — but the version label is wrong. Anyone clicking through to verify will see "ArbOS 31 'Bianca'" as the actual shipped version and lose trust.

**Recommended fix:** Replace all 5 occurrences of `ArbOS 30` with `ArbOS 31` (keep the same forum URL — it's the canonical AIP page, slug notwithstanding). Optionally add `'Bianca'` as KC tends to.
