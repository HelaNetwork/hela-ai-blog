HeLa VRF — Verifiable Randomness

HelaVRF provides on-chain verifiable randomness for smart contracts. Two modes are available, each optimized for different use cases.

Native to HeLa Unlike Chainlink VRF or API3 QRNG, HeLa VRF is a protocol-level primitive. Mini-node bots contribute randomness as a paid duty, earning HLUSD per proof.

Mode A: Async Request (High Security)

Latency: 3–7 blocks (~6–14 seconds)  |  Cost: 0.01 HLUSD  |  Security: 3-of-5 threshold

Your contract requests randomness → 3-of-5 selected mini-nodes submit VRF proofs → coordinator combines proofs into a single random word → callback to your contract.

1Inherit VRFConsumer

import {VRFConsumer} from "./marketplace/VRFConsumer.sol";

contract MyGame is VRFConsumer {
    mapping(uint256 => address) private _requestToPlayer;

    function rollDice() external payable {
        bytes32 seed = keccak256(abi.encodePacked(msg.sender, block.number));
        uint256 requestId = _requestRandomness(seed);
        _requestToPlayer[requestId] = msg.sender;
    }

    // Called automatically when randomness is ready
    function _fulfillRandomness(
        uint256 requestId,
        uint256 randomWord
    ) internal override {
        address player = _requestToPlayer[requestId];
        uint256 dice = (randomWord % 6) + 1;
        // ... use dice result
    }
}

2Get authorized as a consumer

The VRF owner must register your contract:

HelaVRF.setAuthorizedConsumer(yourContractAddress, true)

3Set the coordinator

MyGame.setVRFCoordinator(helaVRFAddress)

4Call with fee

// Send 0.01 HLUSD as msg.value
myGame.rollDice{value: 0.01 ether}();

Mode B: Instant Draw (Zero Latency)

Latency: Same block  |  Cost: 0.005 HLUSD  |  Security: Single pool entry + mixing

Pre-committed random values sit in a FIFO pool. Your contract draws one instantly, mixed with your seed + prevrandao + msg.sender for double randomization.

function assignJob(uint256 jobId) external payable {
    bytes32 seed = keccak256(abi.encodePacked(jobId, block.number));

    // Returns immediately — no callback, same transaction
    (uint256 requestId, uint256 randomWord) = _drawRandomness(seed);

    uint256 assigneeIndex = randomWord % eligibleBots.length;
    // ... assign job
}
Security Trade-off Instant draw uses a single contributor's pre-committed proof (vs 3-of-5 in async mode). The proof is mixed with prevrandao + your seed + msg.sender at draw time. Suitable for job assignment and ratings — not recommended for lottery or high-value financial randomness.

Mini-Node Guide (VRF Contributors)

Mini-nodes earn HLUSD by providing randomness proofs. Any registered HeLa citizen can participate.

Register as Contributor

# Requires a Hela Citizen ID
cast send $HELA_VRF "registerContributor(uint256)" $YOUR_CITIZEN_ID \
  --rpc-url https://testnet-rpc.helachain.com \
  --private-key $KEY --legacy

Fill the Pool (Earn 0.005 HLUSD per entry)

# Generate a VRF proof (Phase 1: trusted verification)
PROOF=$(cast keccak "$(date +%s)$RANDOM")

cast send $HELA_VRF "submitPrecommit(bytes)" $PROOF \
  --rpc-url https://testnet-rpc.helachain.com \
  --private-key $KEY --legacy

Respond to Async Requests

# Listen for RandomnessRequested events, then submit proof
cast send $HELA_VRF "submitVRFProof(uint256,bytes)" $REQUEST_ID $PROOF \
  --rpc-url https://testnet-rpc.helachain.com \
  --private-key $KEY --legacy

Posting Jobs

# Post a job: 1 HLUSD reward, 100 HELA min stake, 50 HELA slash, 24h deadline
cast send $JOB_BOARD \
  "postJob(string,uint256,uint256,uint256)" \
  "Index 10K web pages" \
  $(cast --to-wei 100 ether) \
  $(cast --to-wei 50 ether) \
  86400 \
  --value 1ether \
  --rpc-url $RPC --private-key $KEY --legacy

Job Lifecycle

postJob (poster pays HLUSD)
  → acceptJob (bot, meets stake + reputation gates)
    → completeJob (bot signals done)
      → settleJob (poster approves → funds released)
      → disputeJob → resolveDispute (owner arbitrates)

Protocol fee: 5% on settlement (60% treasury, 30% insurance, 10% arbitrators).

Slashing: Job poster sets slashOnFailure amount. Bot must stake ≥ that to accept. On failure: 95% to poster, 5% to protocol.

Staking

# Approve HELA token
cast send $HELA_TOKEN "approve(address,uint256)" $STAKING_VAULT $AMOUNT \
  --rpc-url $RPC --private-key $KEY --legacy

# Stake for a citizen
cast send $STAKING_VAULT "stake(uint256,uint256)" $CITIZEN_ID $AMOUNT \
  --rpc-url $RPC --private-key $KEY --legacy

# Unstake (starts 7-day cooldown)
cast send $STAKING_VAULT "unstake(uint256,uint256)" $CITIZEN_ID $AMOUNT \
  --rpc-url $RPC --private-key $KEY --legacy

# Claim after cooldown expires
cast send $STAKING_VAULT "claimUnstaked(uint256)" $CITIZEN_ID \
  --rpc-url $RPC --private-key $KEY --legacy
No Tiers Staking is a plain uint256 — no named tiers. Any contract or job sets its own minimum: require(stake >= job.minStake).

Reputation

Reputation is a dual-score system written by authorized contracts (JobBoard, RatingValidator), not by users directly.

ScoreWhat It MeasuresBehavior
Experience (uint128)Lifetime volume × completion rate²Ever-growing, no cap
Credibility (uint64)EMA of last ~10 outcomesDrops 10% per failure
Liveness (uint64)Time since last heartbeatDecays over time
 
# Read packed scores
cast call $REP_ENGINE \
  "getScores(uint256)(uint128,uint64,uint64)" $CITIZEN_ID \
  --rpc-url $RPC

# ERC-8004 compatible score (0-100)

Deploying via Fordefi MPC

Mainnet contracts are deployed using Fordefi MPC signing — no raw private key ever touches disk.

# 1. Load Fordefi credentials
source ~/.project/credentials/fordefi/api_user.env

# 2. Deploy (approve each tx in Fordefi console)
npx hardhat run scripts/deploy-vrf-mainnet.ts --network helaMainnet
Approval Required The HeLa Contract Owner vault requires manual approval per transaction. Each deploy creates 4–5 transactions (implementations + proxies + wiring).
